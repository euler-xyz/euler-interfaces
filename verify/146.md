# Sonic — Deployed Code Verification

Chain ID: 146 · Contracts in scope: 21 · Bytecode matches: **21**

**What a match shows.** For each contract in scope, the code deployed on-chain was rebuilt from the commit in the Source column and compared byte for byte, leaving out what a rebuild cannot reproduce: the compiler's metadata trailer, values set at deployment, and the metadata of contracts a factory deploys. Block explorers are not trusted. A match shows the deployed code is that commit's code. It says nothing about how the contract was initialised or configured, or who controls it.

**What is compared with audited code.** Each deployed commit is compared with the audited version of its code: the code as of the last audit that covered the whole product, with the fixes that audit reviewed. Later, narrower audits are linked where they cover a change. Euler's shared libraries compiled into a contract are compared with their own audited versions. Third-party libraries such as OpenZeppelin, LayerZero and Uniswap are not compared.

**Scope.** 21 contracts on this chain are covered. Not covered: `accountLens`, `adaptiveCurveIRMFactory`, `escrowedCollateralPerspective`, `eulerEarnFactoryPerspective`, `eulerEarnVaultLens`, `eVaultFactoryGovernor`, `eVaultFactoryTimelockController`, `evkFactoryPerspective`, `feeFlowController`, `feeFlowControllerUtil`, `fixedCyclicalBinaryIRMFactory`, `irmLens`, `kinkIRMFactory`, `kinkyIRMFactory`, `oracleLens`, `permit2`, `swapper`, `termsOfUseSigner`, `utilsLens`, `vaultLens` (multisig Safes are not listed).

<details><summary>How to read this report</summary>

- **✅ Matches**: the deployed bytecode equals a rebuild of the commit in the Source column.
- **Since audit**: lines added and removed since the audited version, counting only the files compiled into that contract. **Same as audited**: no change in those files.
- **Older than the audited version**: the deployed commit comes before the audited version. Its diff shows what the audited version adds.
- **Shared library**: Euler library code compiled into several contracts (EVCUtil, SafeERC20Permit2Lib, EulerRouter), compared with the library's own audited version.
- **Dependencies at other commits**: the build that matches the deployment used dependency commits other than the ones the source commit records. The report compares what was actually compiled.
- **Euler note**: a summary of a change written by Euler maintainers. It is not an audit finding.

## EulerSwap

- **eulerSwapV2Implementation** — changed after its audit ([see the changes](#component-euler-swap-v2-81cf6dc9)):
  > **Euler note** (maintainers' summary, not an audit finding)
  > Besides the protocol fee redesign, the code was split to stay under the contract size limit: management functions moved into a separate contract, EulerSwapManagement, which EulerSwap calls by delegatecall and whose address is fixed in the EulerSwap implementation. That contract is checked in this report from the same commit, and its address is confirmed in the implementation's code. The changes also handle vaults that can mint zero shares (as EulerEarn vaults can), and add hardening that landed at the eulerswap-2.0 release, such as keeping a pool locked while it is activated.

- **eulerSwapV2ProtocolFeeConfig** — changed after its audit ([see the changes](#component-euler-swap-v2-81cf6dc9)):
  > **Euler note** (maintainers' summary, not an audit finding)
  > The deployed EulerSwap V2 release (tag eulerswap-2.0) is newer than the code Cantina audited in September 2025, and protocol fees were redesigned since then. In the audited code each pool fixed its fee settings when installed, within 10–25%, and anyone could turn the fee on after one year. In the deployed code every pool reads its fee from one settings contract, EulerSwapProtocolFeeConfig, on each swap. Its admin can set a default fee and per-pool overrides that apply immediately, up to 15% of the LP fee (below the audited 25% maximum); zero is allowed. The admin may not be a known EVC sub-account, a non-zero default fee needs a non-zero default recipient, and every change emits an event. Per-pool overrides are checked only against the 15% limit, and an override without a recipient pays the default recipient. A pool's own LP fee recipient may not be a known EVC sub-account; this is checked when the pool is activated. The pricing curve and quotes are unchanged.
